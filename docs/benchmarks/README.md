# Synthetic evaluation and limits

Run `uv run --extra runtime discuss model-setup --state-dir PATH`, then `uv run --extra runtime python -m scripts.evaluate_speech --state-dir PATH --output METRICS.json`. Model setup is explicit; evaluation does not log in to Discord. Fixtures are original machine-generated speech with provenance under tests/fixtures/synthetic. SQLite used by the suite is temporary and contains synthetic minimal counts only; results contain no transcripts or audio.

The October13 Windows suite uses pinned faster-whisper-small, CPU/int8/two threads. Peak RSS was625MiB and there were no inference subprocesses. It observed **0/1** expected matches in the short clip, **1/3** in the repeated clip and **3/20** in the34-second direct transcription; silence produced0 matches. These are recognition failures, not passing accuracy claims. The longer direct input exceeds the application's12-second segmentation cap and is a decoder stress case, not a deployed chunk. The earlier six-second synthetic fixture happened to produce2/2 matches; it cannot stand in for broader accuracy evidence.

Separate attributed5.19-second streams produced one observed detection per accepted member. One/two/four streams completed in about3.14/5.94/12.41seconds. An immediate eight-stream burst with a four-chunk queue admitted4 and rejected4; accepted work completed with zero processing failures and queue depth never exceeded4. Aggregate decoding throughput was about1.65–1.75audio seconds per compute second on this workstation. That does not support claiming two continuous speakers, unlimited listeners or acceptable response latency under sustained load. Default queue cap in the application is8; evaluation deliberately uses4 to expose overload clearly.

These artificial American-English voices, a short stress passage and burst queue tests leave real accents, natural overlapping conversations, GPU, long-duration soak and live DAVE unqualified. Operators must calibrate recognition errors and actual listener capacity before treating counts as reliable. Results record observed failures instead of silently changing expected words or asserting perfect transcription. Both OS CI explicitly prepares the pinned local model and publishes metrics-only artifacts; unit/quality tests do not require model download or any Discord credentials.
