# Sampled voice replays

Replay is optional and disabled in shipped configuration. Set `servers[].playback.enabled` to `true` to use the defaults: a 900-second cycle, randomized listening/playback timing, at most eight seconds of audio and 1.5 seconds of context around a recognized curse.

For a ten-minute cycle, set `servers[].playback.interval_seconds` to `600`; the shipped default remains `900`. This setting is independent of the Head Hunt channel-evaluation interval and text-report batching interval. See the [combined channel/playback example](configuration.md#separate-quotes-and-leaderboards) and [policy reload guidance](configuration.md#editing-a-running-installation).

Each cycle samples one eligible person the bot currently hears. Selection uses the existing Head Hunt priority list and maximum/minimum/default weights, including in Fixed Channels mode. The bot chooses a random time to start accepting that person's curse clips. Only after the first qualifying clip is captured and available does it choose a random replay time in the remaining interval, leaving room for the clip's duration. Listening start does not schedule playback. No curse or departure before capture means a silent cycle. It never records an unmonitored channel or moves independently of Head Hunt to chase the selected person.

For fixed playback cadence, set `mode` to `"cadence"`: capture is eligible from the cycle start, and an acquired clip plays at the boundary. Random intervals below 60 seconds automatically become cadence and emit a warning. Intervals must be at least five seconds. Short cycles may be silent if recognition does not finish in time.

One pending short clip per server stays in memory only. It never becomes an audio file, SQLite content, a log entry or a backup. Before capture, opt-out/deletion/disable, exclusion/departure or a changed channel cancels the selection. Once captured, a clip remains scheduled even if the person leaves or opts out. It only plays if the original listener is still connected to the original voice channel; it is never rerouted. Reload/shutdown discards RAM-only clips. Playback uses the existing in-process Discord encoder, without FFmpeg or another Python worker. Already transmitted voice cannot be recalled, and other Discord clients may record what they hear.

Request **Speak** under the Developer Portal's **Installation → Default Install Settings → Guild Install** bot permissions, and verify it is allowed by the installed role and current voice-channel overrides. Receiving voice can work while playback is blocked. Check mute/suppression state after permission changes and reconnect if needed; see [Discord setup and troubleshooting](discord-setup.md). The processing notice says captured clips may replay after opt-out. Missing permissions or unavailable playback skips the clip and appears in diagnostics. Recognition and quote boundaries remain approximate; clips are cut to the available recognized chunk rather than retaining a continuous conversation recording.
