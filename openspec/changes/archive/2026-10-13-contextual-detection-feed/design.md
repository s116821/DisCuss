# Design

Each Server has detection_reporting enabled=false, channel_id=null (leaderboard fallback), context_words_per_side=3, interval_seconds=0 and configurable bounded queue/age/page limits. Enabling requires privacy.context_reporting_acknowledged. The primary bot publishes notices/quotes for all listeners, preserving server isolation. The default notice is one concise sentence stating the resolved destination channel name (or a generic fallback), excerpt publication and personal opt-out/in controls; custom listening notices remain intact. Names are resolved from cached source members, with a generic Member fallback; configured timezone identifies each line. Member/server/channel IDs remain internal routing metadata and are omitted from alert text, per the operator feedback during temporary-server testing.

Lexicon matches retain canonical token coordinates. Map normalized token positions to original character spans for case/punctuation-preserving excerpts. Context is clipped at completed STT chunk boundaries. Merge overlapping windows transitively for one speaker/chunk; split oversized groups to fit bounded lines, highlighting only matches counted by each instance. Format quote — speaker, date @ time zone, with an em dash. Match counts remain internal and in standings, omitted from alert text. Escape markup/control text, neutralize mentions and disable embeds; paginate the digest rather than exceed Discord limits.

Counts commit idempotently first. Only newly committed, privacy-allowed detections enter the feed. No snippets/audio/display names enter SQLite or logs. Queue uses per-server instance/UTF8 byte/age limits plus process-wide4096-instance/4MiB cap. Oldest queued instances are evicted on overload and metadata reports drops. Quotes are best-effort: discard on restart/shutdown/reload, opt-out/delete/disable/exclusion, expiry or removed backing chunks. Checking backing chunk metadata also prevents CLI deletion's pending excerpts from posting. Existing count/report semantics remain unchanged.

Independent async delivery tasks per server avoid blocking transcription or calendar publication. Interval windows start with the first pending item; empty windows are silent. A flush snapshots pending instances, batches multiple lines with per-page acknowledgement in memory, removes acknowledged entries and retries unacknowledged entries after bounded delay. Partial successful pages are not resent in normal retry. Lost provider acknowledgements remain at-least-once; no durable quote outbox. Cancel in-flight tasks on privacy changes where possible, but already sent/in-flight Discord content requires operator cleanup. Source config reload drops the queue before changing destination/size/cadence. Manual changing of JSON cannot silently expand retained local transcripts.
