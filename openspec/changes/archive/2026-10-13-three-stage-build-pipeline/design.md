# Design

The job graph is quality → build (Windows/Linux matrix) → release (main push only). Quality runs Ruff/format/ty/pytest, actual analyzer cases, strict specs/archive validation and synthetic speech once. Its optional preview uses semantic-release's real engine with the unchanged analyzer and a temporary local bare mirror containing identical history/tags plus main at the checked source commit; dry-run needs no GitHub write credential and creates no remote tag/release. A local candidate tag supplies Hatchling's version in each main build. PR/doc-only builds use their existing tag-derived development version.

Each platform builds its wheel/sdist and one native archive once, runs installer validation against those exact bytes, and tests two upgrades/rollback using the two latest published platform archives rather than building three artificial versions. Checksums and a source/tag/hash receipt are retained in immutable Actions artifacts. Final publication selects canonical Linux wheel/sdist plus both native archives, verifies every receipt/hash/metadata record, regenerates combined checksums and attests the result. A verifyRelease hook rejects any final semantic-release candidate or source commit differing from the builds before remote tagging. The GitHub plugin uploads those exact files. No static version constant, metadata rewriting, duplicate classifier or post-publication rebuild is introduced. Main workflow concurrency serializes publication; stale source runs safely publish nothing when superseded.
