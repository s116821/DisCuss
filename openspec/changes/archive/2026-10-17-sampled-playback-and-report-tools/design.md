# Design

## Context
The current app captures per-member PCM, transcribes through one bounded local worker and emits ephemeral detection excerpts. The coordinator already owns periodic reconciliation, personal opt-out and report scheduling. Windows boot uses a protected managed interpreter and task; Node manifests own OpenSpec/semantic-release, not Python runtime dependencies. See proposal.md for requested changes.

## Decisions
- Add a playback controller in the same process. It samples only currently monitored eligible members, using existing Head Hunt weights. Default random cycles last 900 seconds, choose a delayed listening start and a playback point after capture before cycle end. Cadence starts capture immediately and plays at the boundary; random intervals below 60 seconds warn and become cadence. Keep one clip per server, default maximum eight seconds and 1.5 seconds of context, bounded to the source chunk/cycle. Nothing is written to disk.
- Preserve word end times for clip trimming. Feed a matching recognized chunk only to its active selected cycle. At capture recheck identity/channel, membership and participation. At playback recheck the original listener/channel and playback permissions; captured clips survive later member changes. Missed/late/expired uncaptured cycles are silent. Use a memory-backed discord.py PCM source and its in-process Opus encoder, with no FFmpeg child. Personal discard cancels only uncaptured selections.
- New speaker labels are escaped Markdown profile links; visible text remains the person's name and the quote format stays quote-first. A bounded quote-history command scans only own bot reports in the configured channel and requires the requester's and bot's history access. Parse local timestamps deterministically, including DST abbreviations. New profile IDs give stable attribution; old plain-name reports require the requested current label plus uniquely confirming existing minimal event metadata for that minute. Unverifiable legacy lines are skipped. No quote database or new chat archive is introduced.
- Add leaderboards.report_channel_id for scheduled reports only; null uses report_channel_id. Detection override/default behavior remains independent. Route access validation through the existing publisher and preserve durable receipts.
- Expose queue age/inference duration in metadata-only health/status; inspect obvious latency causes rather than guessing model/timing changes. Update docs to operator-confirmed Windows use while retaining explicit unqualified accuracy/OS/reboot limits. Use an accessible SVG banner in Discord colors and concise pirate headings without obscuring operational instructions.
- Remove .python-version in both repos and specify Python 3.12 explicitly in CI build/test tools. Keep pyproject/uv.lock as Python dependency authority and package manifests for the required Node tools. Remove release self-tests from CI quality commands; the real preview/release engine remains authoritative and performs actual release validation. Local analyzer fixtures remain available for changes to release code.
- Validate a Windows DisCuss-Service.exe alias using the managed base executable, its DLLs and pyvenv.cfg without another Python interpreter. Preserve the original Python version metadata; the dedicated image name identifies the service. Native CI verifies actual imports and startup. Do not change shared Python binaries or make unconditional OS grouping claims.

## Risks and verification
Speech recognition remains imperfect and serial inference may backlog; expose measurements rather than promise accuracy. Clip playback requires Speak permission and quote history requires Read Message History; missing capability disables the relevant operation with actionable status. Already-published Discord content and voice audio cannot be recalled. Test timing/weights/bounds/privacy/cancellation with synthetic PCM and fake Discord clients; do not test on a production server. Native hosted checks and offline name/import proof precede the protected local upgrade. Preserve token, model cache, statistics and scheduled boot behavior; enable only playback defaults locally and leave period channel override null until the operator asks.

Captured-clip clarification: participation/departure/assignment changes cancel selection only before capture. A captured clip remains scheduled to its original listener/channel even after member departure or opt-out; an unavailable original voice connection skips playback. Reload/shutdown clears RAM.
